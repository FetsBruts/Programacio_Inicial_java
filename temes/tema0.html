Tema 0 · Introducció al curs

Què és programar?

Abans de saber escriure codi cal entendre què és programar: donar instruccions ordenades a un ordinador. En esta sessió escriurem i executarem el nostre primer programa de veritat.

⏱ Sessió curta 🚀 Primer contacte ⌨️ Escriurem codi des del minut zero ☕ Java

Una situació per començar

⏰

Sona el despertador del mòbil. I si el mòbil tinguera una alarma que sona cada dia a les 7:00, però només si l'endemà tens classe? Algú ha hagut d'escriure, pas a pas, què ha de fer el telèfon: mira l'hora, mira el calendari, si demà hi ha classe, sona.

Això és programar. Un programa no és màgia ni intel·ligència: són instruccions ordenades que algú ha pensat abans. Si canvies l'orde, o si t'oblides una instrucció, el resultat canvia.

Durant 10 sessions aprendrem a escriure eixes instruccions en Java. Començarem per un programa que només escriu un missatge per pantalla i acabarem construint programes amb dades, decisions, bucles i objectes.

10-15 min Què significa programar
15-20 min Del codi font al programa
20-25 min El nostre «Hola món!»
10 min Repte de tancament
Abans de començar has de poder fer això:
  • Cap coneixement de programació. Comencem de zero.
  • Un ordinador amb navegador web (els primers dies no cal instal·lar res).
  • Ganes de provar coses i de trencar-les per vore què passa.

Què aprendrem en este tema?

En acabar esta sessió has de saber explicar i fer estes coses:

  • 1Explicar amb les teues paraules què és programar i què és un programa.
  • 2Reconéixer què és el codi font i per a què servix un compilador.
  • 3Escriure i executar un programa senzill que mostre text per pantalla.
  • 4Modificar un programa perquè faça una altra cosa.
  • 5Llegir un missatge d'error bàsic i trobar què falta.

Teoria, poc a poc

Cada idea va amb un exemple. No cal memoritzar res: cal entendre-ho.

1. Programar és donar ordres ordenades

Una recepta de cuina és un programa: si canvies l'orde de les passes, ix malament. La diferència és que ací qui executa les instruccions és un ordinador, que és molt ràpid però no entén res si no li ho diem exactament.

Un ordinador no endevina. Si li demanes «fes la mitjana de les notes», no sap fer-ho. Cal dir-li: demana les notes, suma-les, dividix per quantes n'hi ha, mostra el resultat.

  • Pensar el problema: què volem aconseguir?
  • Dividir-lo en passos xicotets i ordenats.
  • Escriure eixos passos en un llenguatge que l'ordinador entenga.
  • Provar si funciona i corregir el que faça falta.

2. Què és un programa

Un programa és un conjunt d'instruccions guardades en un fitxer que l'ordinador pot executar. Quan l'executes, les instruccions es fan en orde, una darrere d'una altra, de dalt a baix.

ℹ️

Nota mental: si el programa fa una cosa que no esperàvem, normalment és perquè l'orde de les instruccions no és el que pensàvem.

3. Un llenguatge de programació

Per escriure eixes instruccions fem servir un llenguatge de programació: un idioma artificial amb regles. Nosaltres farem servir Java.

Per què Java? Perquè és molt estés (aplicacions, servidors, Android, videojocs), perquè té una comunitat enorme on buscar ajuda i, sobretot, perquè és estricte: t'obliga a dir de quin tipus és cada dada. Eixa exigència, que al principi molesta, ajuda a entendre què està passant dins del programa. És un idioma més per aprendre, i els idiomes s'aprenen practicant.

4. Del codi font al programa

Quan escrivim, el que tenim és codi font: les instruccions escrites per nosaltres (HolaMon.java). L'ordinador entén este codi directament? No. Cal traduir-lo.

📝 Codi font

El que escrivim nosaltres: HolaMon.java. Es pot llegir, se li poden posar comentaris i es pot corregir.

⚙️ Compilació

Un programa anomenat compilador revisa el codi i el traduïx. Si hi ha un error, s'atura i ens avisa.

📦 Fitxer executable

El resultat de compilar. Ja no el llegim nosaltres: el llegix la màquina virtual de Java.

▶️ Execució

La màquina virtual (JVM) executa eixe fitxer i fa les instruccions. Ací veiem el resultat.

💡

Si el compilador s'atura, no passa res: ens està ajudant. Ens diu la línia on s'ha perdut i què no entén. Revisar eixe missatge és part del treball.

5. Com executem el programa

Hi ha dos camins, i els dos són vàlids: en línia (escrius el codi al navegador i polses «Executar») o al teu ordinador (instal·les Java i un editor). El codi que escriurem és exactament el mateix en tots dos casos.

El que importa no és la ferramenta, sinó el que escriuràs. El mateix programa s'executa igual en qualsevol dels dos entorns.

6. El nostre primer programa

Mira'l bé: només hi ha una instrucció que fa faena, la de dins. Les altres són la carcassa que Java necessita per arrancar.

public class HolaMon {
            public static void main(String[] args) {
                System.out.println("Hola món!");
            }
        }
Eixida per pantalla 
Hola món!

System.out.println("...") vol dir, en llenguatge de persones: «System, trau (out) per pantalla i imprimeix una línia (println) amb este text». El text va sempre entre cometes dobles.

S'acaba amb un punt i coma (;). En Java, cada instrucció s'acaba amb ;, com un punt al final d'una frase. Si l'oblides, el compilador s'atura ahí mateix i t'ho diu.

🔧

De moment no necessitem entendre esta part. Les línies public class HolaMon { i public static void main(String[] args) { (i les dos claus }) són la carcassa del programa. Ja arribarem més avant a entendre-les.

7. El nom del fitxer té normes

El fitxer ha de dir-se igual que la classe pública que hi ha dins. Si la classe és HolaMon, el fitxer serà HolaMon.java. Si els canviem de nom, Java no el troba.

⚠️

Java distingix majúscules i minúscules: System, String i HolaMon comencen amb majúscula per conveni, i println va tot en minúscules. Escriure Println o system no funciona.

Exemples explicats pas a pas

Cada exemple: què volem aconseguir, el codi, què apareix per pantalla i per què funciona.

Exemple 1 · Un missatge de benvinguda

Què volem? Que el programa ens salude pel nostre nom.

public class Benvinguda {
            public static void main(String[] args) {
                System.out.println("Hola! Sóc el teu primer programa.");
                System.out.println("Em diuen Java i estic aprenent amb tu.");
            }
        }
Eixida per pantalla 
Hola! Sóc el teu primer programa.
        Em diuen Java i estic aprenent amb tu.

Per què funciona: cada println escriu una línia i, en acabar, baixa a la següent. Si haguérem escrit print (sense ln), tot eixiria enganxat en una sola línia.

Exemple 2 · Una targeta de presentació

Què volem? Presentar-nos amb diverses línies, com si fora una fitxa.

public class Presentacio {
            public static void main(String[] args) {
                System.out.println("=== FITXA DE L'ALUMNE ===");
                System.out.println("Nom:   Ana");
                System.out.println("Curs:  SMX");
                System.out.println("Nivell: principiant absolut");
            }
        }
Eixida per pantalla 
=== FITXA DE L'ALUMNE ===
        Nom:   Ana
        Curs:  SMX
        Nivell: principiant absolut

Per què funciona: l'apòstrof dins del text no dona problemes, però hem d'anar amb compte amb les cometes dobles: si volem escriure una cometa dins del text, hem d'escriure-la com a \".

Exemple 3 · Un dibuix fet amb text

Què volem? Dibuixar una cosa amb caràcters, com es fa als videojocs antics. Ací es veu molt bé que l'orde de les instruccions és el que crea la forma.

public class Dibuix {
            public static void main(String[] args) {
                System.out.println("   *   ");
                System.out.println("  ***  ");
                System.out.println(" ***** ");
                System.out.println("*******");
                System.out.println("   |   ");
            }
        }
Eixida per pantalla 
   *
          ***
         *****
        *******
           |

Per què funciona: cada línia té una quantitat d'espais diferent davant de l'asterisc. Eixos espais són els que fan que la forma crèixca cap als costats.

Què apareixerà per pantalla?

Pensa-ho abans d'executar. Fixa't sobretot en la tercera línia.

Pensa abans d'executar

public class Comptador {
            public static void main(String[] args) {
                System.out.println("Nivell 1");
                System.out.println("Nivell 1 + 1");
            }
        }
Resposta
Eixida real
Nivell 1
        Nivell 1 + 1

Per què: Java no fa les operacions que estan dins de les cometes: allí tot és text. Perquè sumara de veritat, no podríem posar les cometes al voltant de l'operació.

Programació guiada: ho fem junts

Escrivim el nostre primer programa des de zero, pas a pas. No mirem la solució: la construïm.

1

Pensem què volem fer i com es diu el fitxer

Volem un programa que es diga ElMeuPrimerPrograma i que ens salude, diga el curs i ens desitge sort.

Si la classe es dirà ElMeuPrimerPrograma, com s'haurà de dir el fitxer?

El fitxer serà ElMeuPrimerPrograma.java. Ací ja hem après la primera norma de Java.

2

Escrivim la carcassa buida i comprovem que arranca

Dins de la carcassa no hi ha res encara. Provem-ho: un programa buit no fa res i no dona error. Si donara error, sabríem que el problema està en la carcassa.

public class ElMeuPrimerPrograma {
              public static void main(String[] args) {
                  // ací dins escriurem les nostres instruccions
                  // les dues barres fan que Java no llija la línia
              }
          }
3

Afegim la primera instrucció

Una sola línia, i la provem. Sempre: una cosa, provar, i continuar.

public class ElMeuPrimerPrograma {
              public static void main(String[] args) {
                  System.out.println("Bon dia! Soc el teu programa.");
              }
          }
Eixida per pantalla 
Bon dia! Soc el teu programa.

I si llevem el punt i coma? Provem-ho, a vore què diu el compilador.

4

Afegim més instruccions i cuidem l'aspecte

Ara afegim les altres dos línies. Els espais i els salts de línia no afecten el resultat: escrivim el codi de manera que es llija bé.

public class ElMeuPrimerPrograma {
              public static void main(String[] args) {
                  System.out.println("Bon dia! Soc el teu programa.");
                  System.out.println("Este curs aprenem a programar en Java.");
                  System.out.println("Esperem que t'ho passes bé!");
              }
          }
Eixida per pantalla 
Bon dia! Soc el teu programa.
          Este curs aprenem a programar en Java.
          Esperem que t'ho passes bé!

La indentació (els espais del començament de cada línia) no és obligatòria per a Java, però ens ajuda a vore què hi ha dins de què.

5

Trenquem-lo a propòsit

Últim pas i el més important: provoca errors. Lleva una cometa, canvia una majúscula, borra un parèntesi. Llig què diu el compilador cada vegada.

System.out.println("Bon dia!);
                  }

error: unclosed string literal System.out.println("Bon dia!); ^ error: ';' expected 2 errors

El compilador ens diu unclosed string literal: «tens una cadena de text sense tancar». I assenyala amb ^ exactament el lloc on s'ha perdut. Saber llegir eixa fletxa és mig treball de programador.

Mini exercicis

Activitats molt curtes: un minut o dos cada una. Es fan a classe mateix.

1

Canvia el missatge

Fàcil 1 min
Escriu un programa que mostre per pantalla el teu nom.
Solució proposada 
public class ElMeuNom {
    public static void main(String[] args) {
        System.out.println("Ana");
    }
}
Eixida per pantalla 
Ana

Per què es fa aixina: Has canviat només el text que hi ha entre cometes. La carcassa és la mateixa de sempre.

2

Tres línies

Fàcil 2 min
Mostra tres línies: el teu nom, el teu curs i el teu institut.
Solució proposada 
public class TresLinies {
    public static void main(String[] args) {
        System.out.println("Nom: Ana");
        System.out.println("Curs: SMX");
        System.out.println("Institut: IES La Vereda");
    }
}
Eixida per pantalla 
Nom: Ana
Curs: SMX
Institut: IES La Vereda

Per què es fa aixina: Cada println escriu una línia nova. Amb tres instruccions, tres línies.

3

Una cara

Fàcil 2 min
Dibuixa una cara amb caràcters del teclat (ulls, nas i boca).
Solució proposada 
public class Cara {
    public static void main(String[] args) {
        System.out.println("  o   o  ");
        System.out.println("    ^    ");
        System.out.println("  \\___/  ");
    }
}
Eixida per pantalla 
  o   o
    ^
  \___/

Per què es fa aixina: La barra invertida \ és especial en Java: per a escriure una barra de veritat n'hem de posar dos.

4

Sense salts de línia

Fàcil 2 min
Prova de canviar println per print en dos instruccions i mira què passa. Després explica la diferència.
Solució proposada 
public class SenseSalt {
    public static void main(String[] args) {
        System.out.print("SMX ");
        System.out.print("2026");
    }
}
Eixida per pantalla 
SMX 2026

Per què es fa aixina: print no baixa de línia; println sí. Amb print, el que escriguem després continua en la mateixa línia.

5

Troba l'error

Intermèdia 2 min
Este codi no funciona. Copia'l, troba l'error i arregla'l.
public class Trencat {
    public static void main(String[] args) {
        System.out.println("Hola")
        System.out.println("Adéu");
    }
}

Pista: Mira el final de cada línia que fa faena. Totes haurien d'acabar igual.

Solució proposada 
public class Arreglat {
    public static void main(String[] args) {
        System.out.println("Hola");
        System.out.println("Adéu");
    }
}
Eixida per pantalla 
Hola
Adéu

Per què es fa aixina: Falten dos punts i coma. El compilador s'atura en la primera línia que no acaba amb ; i ens assenyala on.

Fes el programa

Tres exercicis complets. Escriu-los sencers, executeu-los i, si donen error, llig el missatge abans de mirar la solució.

1

El meu programa de presentació

Fàcil 15 min
Crea un programa que escriga per pantalla: el teu nom, la teua edat, el teu joc o sèrie preferida i una frase que t'agrade. Cada cosa en una línia, i el nom en la primera.

Pista: Un println per cada línia que vulgues mostrar.

Solució proposada 
public class SocJo {
    public static void main(String[] args) {
        System.out.println("Em dic Ana");
        System.out.println("Tinc 16 anys");
        System.out.println("El meu joc preferit és Minecraft");
        System.out.println("Aprenc a programar perquè vull fer els meus propis jocs.");
    }
}
Eixida per pantalla 
Em dic Ana
Tinc 16 anys
El meu joc preferit és Minecraft
Aprenc a programar perquè vull fer els meus propis jocs.

Per què es fa aixina: Cada línia és una instrucció. Fixa't que el text va sempre entre cometes dobles i que cada instrucció acaba en ;.

2

Un cartell de benvinguda de la teua classe

Fàcil 20 min
Fes un «cartell» fet amb text: una línia de guions a dalt, el nom de la classe, el curs i una línia de guions davall. Després envolta'l amb asteriscs als costats.

Com ha de funcionar:

Exemple d'ús 
(el programa no demana res: només mostra el cartell)
Què ha d'aparéixer 
*************************
*  SMX — 2026 · LA VEREDA  *
*************************

Pista: Compta els caràcters de cada línia perquè totes tinguen la mateixa llargària.

Solució proposada 
public class Cartell {
    public static void main(String[] args) {
        System.out.println("***************************");
        System.out.println("*   SMX — 2026 · LA VEREDA *");
        System.out.println("***************************");
        System.out.println("*   Benvinguts a classe!   *");
        System.out.println("***************************");
    }
}
Eixida per pantalla 
***************************
*   SMX — 2026 · LA VEREDA *
***************************
*   Benvinguts a classe!   *
***************************

Per què es fa aixina: Els asteriscs i els espais es compten a mà: per això el text queda alineat. Per a alinear columnes cal comptar caràcters.

3

El programa que fa preguntes

Intermèdia 20 min
Escriu un programa que mostre tres preguntes i, davall de cada una, la resposta correcta. L'objectiu no és demanar res a l'usuari encara: és practicar moltes línies de text i fixar-se en l'ordre.

Com ha de funcionar:

Exemple d'ús 
(no demana dades encara)
Què ha d'aparéixer 
Pregunta: Quant és 2 + 2?  →  4
Pregunta: Quina és la capital de França?  →  París
Pregunta: Quantes hores té un dia?  →  24

Pista: Cada pregunta i la seua resposta poden anar en la mateixa línia, separades per una fletxa i espais.

Solució proposada 
public class Preguntes {
    public static void main(String[] args) {
        System.out.println("Pregunta: Quant és 2 + 2?  →  4");
        System.out.println("Pregunta: Quina és la capital de França?  →  París");
        System.out.println("Pregunta: Quantes hores té un dia?  →  24");
    }
}
Eixida per pantalla 
Pregunta: Quant és 2 + 2?  →  4
Pregunta: Quina és la capital de França?  →  París
Pregunta: Quantes hores té un dia?  →  24

Per què es fa aixina: La fletxa → és un caràcter més: es pot escriure directament. Els accents també funcionen si el fitxer es guarda amb codificació UTF-8.

Reptes (sense solució)

🧠

Els reptes no tenen botó de solució, a propòsit. L'objectiu és pensar, provar, equivocar-se i tornar-ho a intentar. Es poden resoldre de moltes maneres diferents: totes les solucions que funcionen són bones.

REPTE 1

El logo de la teua marca

Inventa una marca (pot ser de roba, de videojocs, de música o de menjar) i dibuixa el seu logo amb caràcters de text. Ha de tindre com a mínim 6 línies i, si pot ser, alguna forma simètrica.

Quan el tingues, prova de canviar-li el color de fons... no es pot encara! Apunta-ho: ho farem en el Tema 1 amb el nom del company.

Per anar més enllà:

  • Fes dos logos distints en el mateix programa, separats per una línia en blanc.
  • Afig-li un «copyright» amb el nom de la marca.
REPTE 2

El robot de benvinguda

Escriu un programa que parega un robot saludant: que diga hola, que pregunte com estàs i que conteste ell mateix en tres o quatre línies.

No hi ha solució: l'important és que l'orde de les línies tinga sentit, com una conversa.

Per anar més enllà:

  • Que el robot parle dos idiomes: primer en valencià i després en anglés.
  • Que faça un dibuix del robot abans de parlar.

Errors habituals

Estos errors apareixeran segur. Llig-los abans de programar: quan els veges, sabràs què passa.

Error 1

Falta el punt i coma

Codi que falla 
System.out.println("Hola")

error: ';' expected System.out.println("Hola") ^

Què ha passat
Java s'ha trobat una instrucció que no acaba en ; i no sap si ja ha acabat o si falta una cosa més.
Per què
Cada instrucció de Java ha d'acabar en punt i coma. És la manera com Java sap on acaba una ordre i on comença la següent.
Com detectar-ho
El missatge diu ';' expected i assenyala amb ^ el lloc exacte. Sol ser la línia que hi ha just damunt.
Com corregir-ho
Posa el ; al final de la instrucció. Si la instrucció ocupa dos línies, va al final de la segona.
Codi correcte 
System.out.println("Hola");
Error 2

Text sense tancar (cometes)

Codi que falla 
System.out.println("Bon dia!);

error: unclosed string literal System.out.println("Bon dia!); ^

Què ha passat
Java ha trobat l'inici del text (amb ") però no ha trobat on acaba.
Per què
Una cadena de text sempre va entre dos cometes dobles. Si només n'hi ha una, Java continua buscant fins al final de la línia i es perd.
Com detectar-ho
El missatge diu unclosed string literal («cadena de text sense tancar»).
Com corregir-ho
Tanca la cometa: "Bon dia!". Comprova que sigue recta ("), i no una cometa «tipogràfica» (“), que el teclat del mòbil posa de vegades i que Java no entén.
Codi correcte 
System.out.println("Bon dia!");
Error 3

El nom del fitxer no és el de la classe

Codi que falla 
public class ElMeuPrograma {
    public static void main(String[] args) {
        System.out.println("Hola");
    }
}

error: class ElMeuPrograma is public, should be declared in a file named ElMeuPrograma.java

Què ha passat
La classe es diu ElMeuPrograma però el fitxer es diu Programa.java.
Per què
Java busca el codi pel nom del fitxer. Si no coincidixen, no el troba.
Com detectar-ho
El missatge ho diu clarament: should be declared in a file named ....
Com corregir-ho
Canvia el nom del fitxer perquè siga igual que la classe pública, amb la mateixa majúscula i tot: ElMeuPrograma.java.
Codi correcte 
public class ElMeuPrograma {
    public static void main(String[] args) {
        System.out.println("Hola");
    }
}
Error 4

Majúscules i minúscules

Codi que falla 
system.out.println("Hola");

error: package system does not exist

Què ha passat
Hem escrit system en minúscula.
Per què
Java és sensible a les majúscules: System i system són dos noms distints, i el segon no existix.
Com detectar-ho
El compilador diu que no troba package system o que no pot resoldre el símbol.
Com corregir-ho
Escriu-ho igual que sempre: System.out.println(...), amb S majúscula en System i tot println en minúscules.
Codi correcte 
System.out.println("Hola");

Resum visual

Si pots explicar estes sis idees amb les teues paraules, el tema està apamat.

Programar és donar instruccions ordenades a l'ordinador perquè resolga un problema.

Un programa és un fitxer amb instruccions que es fan dalt a baix, en orde.

El codi font el llegim nosaltres; el compilador el traduïx i la màquina virtual l'executa.

System.out.println("...") mostra una línia de text per pantalla; print no baixa de línia.

Cada instrucció acaba en ; i els textos van entre cometes dobles.

Java distingix majúscules i minúscules, i el fitxer ha de dir-se igual que la classe pública.

Un missatge d'error no és un fracàs: ens diu la línia i què no ha entés. Cal llegir-lo.

Autoavaluació

Nou preguntes per comprovar si ho tens clar. No estan ordenades per dificultat: pensa la resposta abans de mirar-la.

  1. Què és programar?

    • Escriure molt de text en un fitxer.
    • Donar instruccions ordenades a l'ordinador perquè resolga un problema.
    • Instal·lar programes a l'ordinador.
    Solució

    Resposta: b) Donar instruccions ordenades a l'ordinador.

    Programar és pensar la solució d'un problema i escriure-la en passos ordenats, en un llenguatge que l'ordinador entenga.

  2. Quina d'estes instruccions mostra correctament un text per pantalla?

    • System.out.println(Hola);
    • System.out.println("Hola");
    • System.out.println("Hola")
    Solució

    Resposta: b) System.out.println("Hola");

    El text va entre cometes dobles i la instrucció acaba en punt i coma. La primera opció no compila perquè Hola no és una variable; la tercera, perquè falta el ;.

  3. Què fa el compilador?

    • Executa el programa.
    • Traduïx el codi font i avisa si hi ha errors.
    • Guarda el fitxer.
    Solució

    Resposta: b) Traduïx el codi font i avisa si hi ha errors.

    El compilador traduïx el que hem escrit a un format que entén la màquina virtual. Si troba alguna cosa mal escrita, s'atura i ens assenyala on.

  4. Escriu (mentalment) què apareixerà per pantalla si executes este programa.

    System.out.println("Nivell 2");
System.out.println("Nivell 2 + 1");
    Solució

    Resposta: Dues línies: Nivell 2 i Nivell 2 + 1.

    Tot el que està entre cometes és text: la suma no es fa. Si volguérem sumar de veritat, no podríem posar les cometes al voltant de l'operació.

  5. Per què el compilador diu «unclosed string literal»?

    System.out.println("Adéu);
    Solució

    Resposta: Perquè falta la cometa que tanca el text.

    Java necessita saber on comença i on acaba el text: per això hi ha dos cometes. Si en falta una, continua buscant i es perd.

  6. Si el fitxer es diu Practica.java i dins la classe es diu Practica1, què passarà?

    Solució

    Resposta: Que no compilarà: si la classe és pública, el fitxer ha de dir-se igual.

    El missatge serà semblant a class Practica1 is public, should be declared in a file named Practica1.java. La solució és fer coincidir els dos noms.

  7. Quina diferència hi ha entre print i println?

    Solució

    Resposta: println escriu el text i baixa de línia; print escriu el text i es queda en la mateixa línia.

    ln ve de line, línia. Amb print podem construir una línia amb diverses instruccions.

  8. Ordena mentalment estes passes del treball d'un programador i digues quina va PRIMER: escriure codi / provar el programa / pensar el problema / dividir-lo en passos.

    Solució

    Resposta: Primer pensar el problema i dividir-lo en passos; després escriure el codi; i finalment provar-lo.

    Escriure codi sense haver pensat el problema és el camí més ràpid per a equivocar-se. Primer les idees, després el teclat.

  9. Un company diu: «el meu programa no funciona, segur que Java està roín». Què comprovaries primer?

    Solució

    Resposta: Els errors típics: punt i coma, cometes, el nom del fitxer i les majúscules de System i println.

    Gairebé tots els errors del principi són d'eixos quatre tipus, i el compilador ens diu en quina línia mirar. Sempre es llig el missatge abans de tocar res.
