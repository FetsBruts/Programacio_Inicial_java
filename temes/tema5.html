Mètodes: reutilitzar el codi

Fins ara el codi creix cap avall i cada programa és una sola llista de coses. Els mètodes ens deixen donar un nom als trossos de programa i construïr el programa com qui monta un joc de peces.

⏱ 3 hores 📦 Fase 2 · Estructurar el programa 🧩 Necessites: Temes 0 a 4 ❓ La pregunta clau: quines peces té este problema?

Una situació per començar

🧱

En el tema anterior hem fet un programa que calcula la mitjana d'un array. Al tema 3 en vam fer un altre que calcula la mitjana de notes llegides pel teclat. I en el tema 2 un altre que diu la qualificació d'una nota.

Hi ha una cosa que no ens ha cridat l'atenció però que és un problema seriós: hem escrit el mateix codi una vegada i una altra. I quan el codi està repetit, qualsevol canvi cal fer-lo en tots els llocs… i sempre se n'oblida algun.

// a dins de main, per a les notes de classe:
          double suma1 = 0;
          for (int i = 0; i < notes.length; i++) {
              suma1 = suma1 + notes[i];
          }
          double mitjanaNotes = suma1 / notes.length;

          // ...i un poc més avall, per als punts del joc:
          double suma2 = 0;
          for (int i = 0; i < punts.length; i++) {
              suma2 = suma2 + punts[i];
          }
          double mitjanaPunts = suma2 / punts.length;

Són els mateixos càlculs amb noms diferents. I si ens equivocàvem en un? Hauríem d'arreglar-ho dos vegades.

La solució: guardar eixe tros de programa amb un nom i usar el nom cada vegada que el necessitem. Es diu mètode (o funció, en molts llenguatges). Ja els has estat usant tot el temps: println, nextInt, length(), equals… són mètodes que algú altre ha escrit per nosaltres!

Què aprendrem en este tema?

En acabar esta sessió has de saber fer estes coses:

  • 1Escriure un mètode (public static) i cridar-lo les vegades que calga.
  • 2Passar dades a un mètode amb paràmetres.
  • 3Traure un resultat d'un mètode amb return.
  • 4Diferenciar els mètodes void dels que tornen un valor.
  • 5Passar arrays a un mètode i treballar amb ells.
  • 6Dividir un problema gran en mètodes menuts i organitzar-ho des de main.

Teoria, poc a poc

Una idea → un exemple. I una pregunta nova: quin nom li posaria a cada peça?

1. Un mètode és codi amb nom

Un mètode és un tros de programa guardat amb un nom, que podem usar quan volem. Este mètode escriu un salud, i anomenem-lo des de main tres vegades:

public class Saluda {
            public static void saluda() {
                System.out.println("Hola! Soc un mètode.");
            }

            public static void main(String[] args) {
                saluda();
                saluda();
                saluda();
            }
        }
Eixida per pantalla 
Hola! Soc un mètode.
        Hola! Soc un mètode.
        Hola! Soc un mètode.

Fixa't en les tres parts del mètode:

  1. El cap: public static void saluda(). Diu com es diu i què torna.
  2. El cos: tot el que va entre { }. És el que fa.
  3. La crida: saluda(); des de main. Ací és on s'executa.
💡

public static són dos paraules que de moment escriguem sempre igual, tal qual, com una fórmula. Encara no cal entendre-les; al Tema 6 vorem què signifiquen i per què main també les porta.

2. Mètodes que necessiten dades: paràmetres

El mètode anterior sempre diu el mateix. Perquè servisca per a qualsevol cosa, li passem les dades que necessita entre els parèntesis. Es diuen paràmetres.

public class SaludaAlgu {
            public static void saluda(String nom) {
                System.out.println("Hola, " + nom + "!");
            }

            public static void main(String[] args) {
                saluda("Ana");
                saluda("Bruno");
                saluda("Carla");
            }
        }
Eixida per pantalla 
Hola, Ana!
        Hola, Bruno!
        Hola, Carla!

String nom vol dir: «este mètode necessita un text i dins del mètode es dirà nom». El valor que li donem en cridar-lo ("Ana") se'n diu argument.

Parlant de…On estàExemple
ParàmetreEn el cap del mètodeString nom
ArgumentEn la cridasaluda("Ana")
Variable localDins del cos del mètodeint suma = 0;
💡

Poden haver-hi diversos paràmetres, separats per comes i cadascun amb el seu tipus: public static double mitjana(double a, double b). I es poden passar tants arguments com paràmetres tinga el mètode, ni un més ni un menys.

3. Mètodes que tornen un resultat: return

Fins ara els nostres mètodes escriuen coses per pantalla. Però el més útil és que calculen i ens tornen el resultat, perquè nosaltres decidim què fem amb ell.

public class SumaMetode {
            public static int suma(int a, int b) {
                return a + b;      // ací es torna el resultat
            }

            public static void main(String[] args) {
                int resultat = suma(4, 7);
                System.out.println("4 + 7 = " + resultat);

                System.out.println("10 + 32 = " + suma(10, 32));
            }
        }
Eixida per pantalla 
4 + 7 = 11
        10 + 32 = 42

Tres idees clau d'este exemple:

  1. El cap canvia void per int: «este mètode torna un número enter».
  2. return fa dos treballs: torna el valor i acaba el mètode allí mateix.
  3. El resultat es pot guardar en una variable o usar-lo directament dins d'una altra operació.
⛔

Si un mètode diu que torna un int, ha de tornar un int en tots els camins possibles. Vore's un if sense else dins d'un mètode que ha de tornar alguna cosa és el motiu de l'error «This method must return a result of type int».

4. void o amb retorn?

La diferència és què volem d'eixe mètode: que faça alguna cosa (mostrar, dibuixar, guardar) o que ens done un valor.

public class Calculs {
            public static void mostraMissatge(String text) {   // no torna res: void
                System.out.println(">>> " + text);
            }

            public static double mitjana(double a, double b) { // torna un double
                return (a + b) / 2;
            }

            public static boolean esParell(int n) {            // torna un boolean
                return n % 2 == 0;
            }

            public static void main(String[] args) {
                mostraMissatge("Comencem");

                System.out.println("Mitjana de 6 i 9: " + mitjana(6, 9));
                System.out.println("El 7 és parell? " + esParell(7));

                if (esParell(8)) {
                    mostraMissatge("El 8 sí que és parell");
                }
            }
        }
Eixida per pantalla 
>>> Comencem
        Mitjana de 6 i 9: 7.5
        El 7 és parell? false
        >>> El 8 sí que és parell

Un mètode que torna boolean és especialment útil dins d'un if: if (esParell(8)) es llig com una frase en valencià. Això fa el codi molt més llegible.

TipusQuè faExemple d'ús
voidFa faena i no torna resmostraMissatge("Hola");

5. Cada variable viu dins del seu mètode

Una variable creada dins d'un mètode només existix allí dins. Fora no es veu. Esta idea pareix una limitació i és justament el que fa els programes ordenats.

public class Ambit {
            public static void calcula() {
                int dins = 5;
                System.out.println("Dins del mètode: " + dins);
            }

            public static void main(String[] args) {
                calcula();

                int dins = 99;
                System.out.println("En main: " + dins);

                // System.out.println(dinsDelMetode);  // això NO existix: donaria error
            }
        }
Eixida per pantalla 
Dins del mètode: 5
        En main: 99
⛔

Per això main i calcula poden tindre dos variables amb el mateix nom sense cap problema: són dos móns separats. Si un mètode necessita una dada, se li passem per paràmetre o ens la torna amb return. Als dos móns només s'arriba per la porta (els paràmetres i el retorn).

6. Mètodes que treballen amb arrays

Els arrays es passen als mètodes igual que qualsevol altra dada. Este és el gran estalvi: els càlculs de mitjana, màxim o mínim es fan una sola vegada i s'usen sempre.

public class AmbArray {
            public static double mitjana(double[] valors) {
                double suma = 0;
                for (int i = 0; i < valors.length; i++) {
                    suma = suma + valors[i];
                }
                return suma / valors.length;
            }

            public static int maxim(int[] valors) {
                int max = valors[0];
                for (int i = 1; i < valors.length; i++) {
                    if (valors[i] > max) {
                        max = valors[i];
                    }
                }
                return max;
            }

            public static void main(String[] args) {
                double[] notes = {6, 7, 6, 9, 8};
                int[] punts = {120, 95, 180, 60};

                System.out.println("Mitjana: " + mitjana(notes));
                System.out.println("Màxim: " + maxim(punts));
            }
        }
Eixida per pantalla 
Mitjana: 7.2
        Màxim: 180

Dins del mètode, l'array es diu valors, i fora es diu notes o punts. El nom del paràmetre és cosa del mètode: qui el crida només ha de passar-li un array del tipus correcte.

ℹ️

Fixat que mitjana i maxim no escriuen res per pantalla: només calculen. Això les fa reutilitzables: a un programa voldrem mostrar la mitjana, a un altre potser comprovar si aprova la classe.

7. Mètodes que criden altres mètodes

Un mètode pot usar un altre mètode, i així es construïxen programes com qui monta peces.

public class Butlleti {
            public static void linia() {
                System.out.println("----------------------");
            }

            public static void capcalera(String nom) {
                linia();
                System.out.println("BUTLLETÍ DE " + nom.toUpperCase());
                linia();
            }

            public static void main(String[] args) {
                capcalera("Ana");
                System.out.println("Nota: 8.5");
                linia();
            }
        }
Eixida per pantalla 
----------------------
        BUTLLETÍ DE ANA
        ----------------------
        Nota: 8.5
        ----------------------

capcalera usa linia dos vegades. Si un dia volem una línia més llarga, la canviem en un sol lloc i tots els butlletins queden bé. Eixe és el poder dels mètodes.

8. Pensar el problema en peces

La manera de treballar amb mètodes és pensar el problema en verbs: quins passos té i quin nom li donaria a cada pas. És el que es diu dissenyar de dalt a baix.

Exemple: «llegir 5 notes i mostrar un informe amb la mitjana, la nota més alta i la qualificació».

Pas (què cal fer)Nom del mètodeQuè torna
Demanar les notes pel teclatllegirNotes(int quants)double[]
Calcular la mitjanamitjana(double[] notes)double
Trobar la nota més altamaxim(double[] notes)double
Convertir la nota en textqualificacio(double nota)String
Escriure l'informemostraInforme(double[] notes)void

I main queda reduït a l'esquelet del programa: llegir, mostrar. Cada peça es pot provar per separat, i si alguna cosa no funciona, ja saps on mirar.

💡

Regla pràctica: si un tros de codi et costa d'explicar en una frase, probablement hauria de ser un mètode. I si li has de posar un comentari llarg per explicar-lo, segur que hauria de ser un mètode.

Exemples explicats pas a pas

Cada exemple: què volem aconseguir, el codi, què apareix per pantalla i per què funciona.

Exemple 1 · Conversor de temperatures

Què volem? Convertir graus Celsius a Fahrenheit i al revés. Si la conversió està dins d'un mètode amb nom, el programa principal queda claríssim.

public class Conversor {
            public static double celsiusAFahrenheit(double celsius) {
                return celsius * 9 / 5 + 32;
            }

            public static double fahrenheitACelsius(double fahrenheit) {
                return (fahrenheit - 32) * 5 / 9;
            }

            public static void main(String[] args) {
                System.out.println("0 graus C = " + celsiusAFahrenheit(0) + " F");
                System.out.println("25 graus C = " + celsiusAFahrenheit(25) + " F");
                System.out.println("100 graus C = " + celsiusAFahrenheit(100) + " F");
                System.out.println("La febra (38 C) = " + celsiusAFahrenheit(38) + " F");
                System.out.println("Tornem: " + fahrenheitACelsius(98.6) + " graus C");
            }
        }
Eixida per pantalla 
0 graus C = 32.0 F
        25 graus C = 77.0 F
        100 graus C = 212.0 F
        La febra (38 C) = 100.4 F
        Tornem: 37.0 graus C

Per què funciona: la fórmula està escrita una sola vegada en el seu mètode. Si un dia la volem canviar (o hem escrit 9/5 al revés), hi ha un únic lloc on tocar.

💡

Fixa't en la línia del main: es llig com si parlàrem. «La febra, 38 graus, quants F són?» → celsiusAFahrenheit(38). Este és el senyal que els mètodes estan ben pensats.

Exemple 2 · La qualificació, ara amb mètode

Què volem? Convertir una nota numèrica en text (Insuficient, Suficient…). Ho fem dins d'un mètode que torna un String.

public class Qualificacio {
            public static String qualificacio(double nota) {
                if (nota < 5) {
                    return "Insuficient";
                } else if (nota < 6) {
                    return "Suficient";
                } else if (nota < 7) {
                    return "Bé";
                } else if (nota < 9) {
                    return "Notable";
                } else {
                    return "Excel·lent";
                }
            }

            public static void main(String[] args) {
                System.out.println("4.5 → " + qualificacio(4.5));
                System.out.println("5.5 → " + qualificacio(5.5));
                System.out.println("6.5 → " + qualificacio(6.5));
                System.out.println("8.0 → " + qualificacio(8.0));
                System.out.println("9.5 → " + qualificacio(9.5));
            }
        }
Eixida per pantalla 
4.5 → Insuficient
        5.5 → Suficient
        6.5 → Bé
        8.0 → Notable
        9.5 → Excel·lent

Per què funciona: cada return acaba el mètode immediatament, així que no cal guardar la resposta en una variable. Com que hi ha un else final que sempre torna alguna cosa, el mètode sempre torna un text: no hi ha cap camí que acabe sense return.

⛔

Esta versió és millor que la del tema 2: ara la qualificació es pot usar per a qualsevol nota del programa, i la podem mostrar, guardar o comparar. Un mètode que torna un valor és una peça que es pot usar en qualsevol lloc.

Exemple 3 · Un gràfic de barres

Què volem? Mostrar un gràfic de les notes fet amb caràcters. Necessitem un mètode que faça una barra de la llargària que li diguem.

public class Grafic {
            public static void barra(int estrelles) {
                for (int i = 0; i < estrelles; i++) {
                    System.out.print("*");
                }
                System.out.println();
            }

            public static void graficDeNotes(int[] notes) {
                for (int i = 0; i < notes.length; i++) {
                    System.out.print("Alumne " + (i + 1) + ": ");
                    barra(notes[i]);
                }
            }

            public static void main(String[] args) {
                int[] notes = {6, 9, 4, 8, 7};
                graficDeNotes(notes);
            }
        }
Eixida per pantalla 
Alumne 1: ******
        Alumne 2: *********
        Alumne 3: ****
        Alumne 4: ********
        Alumne 5: *******

Per què funciona: barra sap dibuixar una barra de la llargària que li demanem. graficDeNotes recorre l'array i crida barra una vegada per alumne, passant-li la seua nota. Les dos peces són independents: podríem usar barra en qualsevol altre programa.

💡

System.out.print (sense ln) escriu en la mateixa línia, i el println() buit del final de barra baixa de línia. La barra es fa amb un bucle for on el comptador no s'usa dins: només conta voltes.

Exemple 4 · Mètodes que comproven dades

Què volem? Que el programa no accepte notes impossibles. Un mètode que torna boolean és la ferramenta perfecta per a preguntar «açò és vàlid?».

public class Validacio {
            public static boolean esNotaValida(double nota) {
                return nota >= 0 && nota <= 10;
            }

            public static boolean esAprovat(double nota) {
                return nota >= 5;
            }

            public static void main(String[] args) {
                System.out.println("¿6.5 és vàlida? " + esNotaValida(6.5));
                System.out.println("¿12 és vàlida? " + esNotaValida(12));
                System.out.println("¿-3 és vàlida? " + esNotaValida(-3));
                System.out.println("¿4.9 està aprovada? " + esAprovat(4.9));
                System.out.println("¿5.0 està aprovada? " + esAprovat(5.0));
            }
        }
Eixida per pantalla 
¿6.5 és vàlida? true
        ¿12 és vàlida? false
        ¿-3 és vàlida? false
        ¿4.9 està aprovada? false
        ¿5.0 està aprovada? true

Per què funciona: un mètode que torna boolean és una pregunta amb nom. esNotaValida(12) es llig com una pregunta i tornaaa false. Amb estes preguntes fetes mètodes, el programa principal queda ple de frases que s'entenen.

💡

Costum de bo programador: els mètodes que tornen boolean es diuen començant per es o te: esParell, esAprovat, teCarnet, esNotaValida. Qui llig el codi ja sap què torna.

Què torna este mètode?

Llig el mètode amb atenció i pensa el resultat de les tres crides abans d'executar-lo.

Pensa abans d'executar

public class Misteri {
            public static int misteri(int a, int b) {
                if (a > b) {
                    return a;
                }
                return b;
            }

            public static void main(String[] args) {
                System.out.println(misteri(3, 9));
                System.out.println(misteri(7, 2));
                System.out.println(misteri(5, 5));
            }
        }
Resposta
Eixida real
9
        7
        5

Per què: El mètode torna el número més gran dels dos. Quan a > b torna a i el mètode acaba allí mateix; si no, arriba al segon return i torna b. Amb 5 i 5 no es complix a > b (5 no és més gran que 5), així que torna b, que val el mateix: 5.

Programació guiada: ho fem junts

Farem un analitzador de notes dividit en mètodes: llegir, calcular, qualificar i mostrar. Cada peça, un mètode. I ho provarem peça a peça.

1

El problema i el seu esquelet

Volem un programa que demane 4 notes, mostre la mitjana, la nota més alta, els aprovats i la qualificació final.

Abans d'escriure res, pensem el programa en verbs i decidim què torna cada peça:

Quin d'estos mètodes no necessita tornar res? Per què?

2

Primer mètode: llegir les notes

Comencem pel mètode que demana les dades. Torna un array, i eixa és una idea nova però molt còmoda: el mètode fabrica l'array i ens el dóna.

import java.util.Scanner;

          public class Analitzador {
              public static double[] llegirNotes(int quants) {
                  Scanner teclat = new Scanner(System.in);
                  double[] notes = new double[quants];

                  for (int i = 0; i < notes.length; i++) {
                      System.out.print("Nota " + (i + 1) + ": ");
                      notes[i] = teclat.nextDouble();
                  }

                  return notes;
              }

              public static void main(String[] args) {
                  double[] notes = llegirNotes(4);

                  System.out.println("He guardat " + notes.length + " notes.");
                  System.out.println("La primera és " + notes[0]);
              }
          }
Què ha de passar 
Nota 1: 6
          Nota 2: 7
          Nota 3: 6
          Nota 4: 9
          He guardat 4 notes.
          La primera és 6.0

El paràmetre int quants diu quantes notes volem. El return notes; torna l'array ja ple. En main ho guardem: double[] notes = llegirNotes(4);.

3

Els càlculs, en mètodes separats

Ara els tres càlculs. Fixa't que són els del tema anterior, però ben empaquetats: es poden usar en qualsevol programa.

public class Analitzador {
              public static double mitjana(double[] notes) {
                  double suma = 0;
                  for (int i = 0; i < notes.length; i++) {
                      suma = suma + notes[i];
                  }
                  return suma / notes.length;
              }

              public static double maxim(double[] notes) {
                  double max = notes[0];
                  for (int i = 1; i < notes.length; i++) {
                      if (notes[i] > max) {
                          max = notes[i];
                      }
                  }
                  return max;
              }

              public static int aprovats(double[] notes) {
                  int quants = 0;
                  for (int i = 0; i < notes.length; i++) {
                      if (notes[i] >= 5) {
                          quants++;
                      }
                  }
                  return quants;
              }

              public static void main(String[] args) {
                  double[] notes = {6, 7, 6, 9};

                  System.out.println("Mitjana: " + mitjana(notes));
                  System.out.println("Més alta: " + maxim(notes));
                  System.out.println("Aprovats: " + aprovats(notes));
              }
          }
Eixida per pantalla 
Mitjana: 7.0
          Més alta: 9.0
          Aprovats: 4
💡

Prova els mètodes per separat: canvia l'array del main per {2, 3, 1, 4} i comprova que la mitjana és 2.5, la més alta 4.0 i els aprovats 0. Provar peces menudes és quasi sempre més fàcil que provar el programa sencer.

4

La qualificació, un mètode que torna text

Ara la peça que convertix la nota en text. Es pot provar tota sola amb notes de la frontera.

import java.util.Scanner;

public class RankingMetodes {
    public static int[] llegirPunts(int quants) {
        Scanner teclat = new Scanner(System.in);

        for (int i = 0; i < punts.length; i++) {

        return suma;

    public static double mitjana(int[] valors) {
        return total(valors) / (double) valors.length;

Reptes (sense solució)

🧠

Els reptes no tenen botó de solució, a propòsit. L'objectiu és pensar, provar, equivocar-se i tornar-ho a intentar. Es poden resoldre de moltes maneres diferents: totes les solucions que funcionen són bones.

REPTE 1

El joc de les endevinalles, amb mètodes

Fes el joc d'endevinar el número (Tema 3) dividit en mètodes: un que demane un número vàlid a l'usuari, un que done la pista («més gran» o «més menut»), un que comprove si s'ha encertat i un que mostre el resultat final amb els intents.

El repte és decidir què torna cada mètode: el que demana el número torna un int, el de la pista no torna res (void, només escriu), el de comprovar torna un boolean… Pensar les firmes abans d'escriure el codi és mitat de la faena.

Afig una dificultat: l'usuari pot triar entre 1 i 10 intents i el programa ha de demanar el nivell en un mètode a banda.

Per anar més enllà:

  • Que el número secret es genere sol amb (int) (Math.random() * 100) + 1.
  • Un mètode que torne la temperatura de l'intent: «calent» si la diferència és menuda, «fred» si és gran.
  • Comptar les partides guanyades i perdudes i mostrar un resum al final.
REPTE 2

La biblioteca pròpia de ferramentes

Crea una classe Ferramentes amb mètodes que pugues reutilitzar en qualsevol programa. Com a mínim: esParell(int n), maxim(int[] valors), minim(int[] valors), mitjana(int[] valors), comptaVocals(String text), invertix(String text) (que torne el text del revés) i esPrimer(int n).

Després escriu un segon programa que use eixa biblioteca per a tres coses distintes. Eixe és l'objectiu real del tema: escriure una vegada i usar sempre.

esPrimer(int n) és el més interessant: un número és primer si només es pot dividir per 1 i per si mateix. Pensa com ho comprovaries amb un bucle i una variable bandera… i compte amb l'1 i amb el 2, que són casos especials.

Per anar més enllà:

  • Afig arredona(double valor, int decimals).
  • Afig conte(int[] valors, int buscat) que torne boolean.
  • Afig posicioDe(String[] llista, String buscat) que torne la posició o -1 si no està.

Errors habituals

Els errors d'este tema parlen quasi sempre de tres coses: els tipus, els parèntesis i el return.

Error 1

Oblidar el return en un mètode que ha de tornar un valor

Codi que falla 
public static int suma(int a, int b) {
    System.out.println(a + b);
}

error: This method must return a result of type int public static int suma(int a, int b) { ^^^^^^^^^^^^^^^^^^

Què ha passat
El programa no compila.
Per què
El cap del mètode diu que torna un int, però el cos no torna res: només escriu per pantalla. println mostra el valor a la persona, però no el torna al programa.
Com detectar-ho
El missatge és clar: This method must return a result of type int. També apareix si el return està dins d'un if sense else i hi ha un camí que no torna res.
Com corregir-ho
Fes servir return a + b; si vols tornar el valor, o canvia el cap a public static void si el que vols és mostrar-lo. Les dos coses alhora no es poden: o es torna un valor o no es torna.
Codi correcte 
public static int suma(int a, int b) {
    return a + b;
}
Error 2

Passar arguments del tipus equivocat

Codi que falla 
public static int suma(int a, int b) {
    return a + b;
}

public static void main(String[] args) {
    int r = suma(2.5, 3.5);  // ERROR
}

error: The method suma(int, int) in the type Mal is not applicable for the arguments (double, double) int r = suma(2.5, 3.5); ^^^^

Què ha passat
El programa no compila.
Per què
El mètode espera dos int i li passem dos double. Java no convertix un double a int automàticament perquè es perdrien decimals.
Com detectar-ho
El missatge diu «not applicable for the arguments» i mostra els tipus que has passat.
Com corregir-ho
Canvia els tipus del mètode perquè coincidisquen amb les dades (double en compte de int), o passa-li enters si el mètode és d'enters.
Codi correcte 
public static double suma(double a, double b) {
    return a + b;
}

public static void main(String[] args) {
    double r = suma(2.5, 3.5);
}
Error 3

Cridar un mètode amb menys paràmetres dels que demana

Codi que falla 
public static void saluda(String nom) {
    System.out.println("Hola, " + nom);
}

public static void main(String[] args) {
    saluda();   // ERROR: falta el text
}

error: The method saluda(String) in the type Mal is not applicable for the arguments () saluda(); ^^^^^^

Què ha passat
El programa no compila.
Per què
El mètode necessita un text per a funcionar. Sense ell, no sabria a qui saludar.
Com detectar-ho
El missatge mostra el mètode amb el seu paràmetre —saluda(String)— i els arguments que has passat —(), buit—.
Com corregir-ho
Passa-li tots els arguments que demana: saluda("Ana"). Els parèntesis de la crida han de portar tants valors com paràmetres tinga el cap del mètode.
Codi correcte 
public static void saluda(String nom) {
    System.out.println("Hola, " + nom);
}

public static void main(String[] args) {
    saluda("Ana");
}
Error 4

Oblidar el static

Codi que falla 
public static void main(String[] args) {
    saluda();   // ERROR
}

public void saluda() {
    System.out.println("Hola");
}

error: Cannot make a static reference to the non-static method saluda() from the type Mal saluda(); ^^^^^^

Què ha passat
El programa no compila i assenyala la crida.
Per què
main és un mètode especial: pot cridar directament els mètodes que també siguen estàtics. Als que no ho són, no pot arribar així.
Com detectar-ho
Missatge Cannot make a static reference to the non-static method.
Com corregir-ho
De moment, i fins al Tema 6, posa static en tots els mètodes de la classe. Al tema següent descobrirem què significa exactament.
Codi correcte 
public static void main(String[] args) {
    saluda();
}

public static void saluda() {
    System.out.println("Hola");
}
Error 5

Definir un mètode dins d'un altre mètode

Codi que falla 
public static void main(String[] args) {
    System.out.println("Hola");

    public static void saluda() {   // ERROR
        System.out.println("No es pot ficar ací");
    }
}

error: Syntax error on token "saluda", AnnotationName expected after this token public static void saluda() { ^^^^^

Què ha passat
El programa no compila i el missatge parla d'una «annotation» que no entenem.
Per què
En Java, els mètodes es definixen un darrere l'altre, tots dins de la classe, mai dins del cos d'un altre mètode.
Com detectar-ho
Missatge estrany al principi del mètode definit a dins. Si el missatge no té sentit, mira si et falta una clau } per a tancar el mètode anterior.
Com corregir-ho
Tanca el mètode amb } i definix el nou mètode fora, junt als altres, dins de la classe.
Codi correcte 
public static void saluda() {
    System.out.println("Hola desde saluda");
}

public static void main(String[] args) {
    saluda();
}
Error 6

Esperar que un mètode void done un valor

Codi que falla 
public static void mostra(int n) {
    System.out.println("Valor: " + n);
}

public static void main(String[] args) {
    int x = mostra(5);   // ERROR: un void no torna res
}
Què ha passat
El programa no compila: no es pot guardar en una variable el resultat d'un mètode void.
Per què
Un void no torna res, així que no hi ha res per a guardar. El mètode ja ha fet la seua faena (escriure per pantalla).
Com detectar-ho
El missatge parla de «void cannot be converted to int» o paregut, segons el cas.
Com corregir-ho
O bé crides el mètode sense guardar res (mostra(5);), o bé si vols el valor, canvia el mètode perquè torne el valor amb return i un tipus en el cap.
Codi correcte 
public static void mostra(int n) {
    System.out.println("Valor: " + n);
}

public static void main(String[] args) {
    mostra(5);
}

Resum visual

Les idees que has d'endur-te d'este tema.

Un mètode és un tros de programa amb nom que es pot cridar les voltes que calga.

El cap diu com es diu i què torna; el cos diu què fa.

Els paràmetres són les dades que el mètode necessita; els arguments són els valors que li passem.

void = no torna res; qualsevol altre tipus = return que torna un valor d'eixe tipus.

return torna el valor i acaba el mètode immediatament.

Si un mètode diu que torna alguna cosa, tots els camins han de tornar-la.

Les variables d'un mètode només existixen dins d'eixe mètode (àmbit).

Als mètodes es passen arrays com qualsevol altra dada, i es poden tornar arrays.

Un mètode pot cridar altres mètodes: el programa es construïx com un joc de peces.

main hauria de ser l'esquelet: crides a mètodes amb noms que s'entenen.

Autoavaluació

Nou preguntes. Pensa-les abans de mirar la solució.

  1. Què significa void en el cap d'un mètode?

    • Que el mètode està buit i no fa res
    • Que el mètode no torna cap valor
    • Que el mètode no necessita paràmetres
    Solució

    Resposta: b) Que el mètode no torna cap valor.

    Un mètode void pot fer molta faena (escriure, dibuixar, guardar), però no torna res: no es pot guardar el seu resultat en una variable.

  2. Quantes vegades apareix per pantalla «Hola» amb este codi?

    public static void saluda() {
    System.out.println("Hola");
}

public static void main(String[] args) {
    saluda();
    saluda();
}
    Solució

    Resposta: Dos vegades.

    El mètode es defineix una vegada i es crida dos. Escriure un mètode no l'executa: només el deixa preparat. S'executa en el moment de la crida.

  3. Quina diferència hi ha entre paràmetre i argument?

    Solució

    Resposta: El paràmetre està en el cap del mètode (String nom); l'argument és el valor que es passa en la crida (saluda("Ana")).

    El paràmetre és el nom que li donem a la dada dins del mètode; l'argument és la dada concreta de cada crida.

  4. Este mètode no compila. Per què?

    public static int dobla(int n) {
    System.out.println(n * 2);
}
    Solució

    Resposta: Perquè diu que torna un int, però no té cap return.

    println mostra el valor en pantalla, però no el torna. El missatge del compilador és This method must return a result of type int. Si el que volem és mostrar, el mètode hauria de ser void.

  5. Escriu un mètode que torne el número més gran de dos enters.

    Solució

    Resposta: public static int maxim(int a, int b) { if (a > b) { return a; } return b; }

    Cap dels dos camins es queda sense tornar res: si a > b torna a, i si no, arriba al return b. Els dos return són vàlids perquè el mètode diu int.

  6. Quina diferència hi ha entre System.out.println(x); i return x; dins d'un mètode?

    Solució

    Resposta: println mostra el valor a la pantalla; return torna el valor al programa i acaba el mètode.

    Són dos móns distints: un és per a la persona que usa el programa, l'altre és perquè el programa puga seguir treballant amb eixe valor.

  7. Este codi dona error. Per què?

    public static void main(String[] args) {
    int resultat = mostra(5);
}

public static void mostra(int n) {
    System.out.println("Valor: " + n);
}
    Solució

    Resposta: Perquè mostra és void i no torna res, així que no es pot guardar en una variable.

    Si vols el valor per a treballar amb ell, el mètode ha de tornar-lo: public static int mostra(int n) { return n; }. Si només vols escriure'l, crida'l sense assignar: mostra(5);.

  8. Escriu un mètode que calcule la mitjana d'un array double[] notes.

    Solució

    Resposta: public static double mitjana(double[] notes) { double suma = 0; for (int i = 0; i < notes.length; i++) { suma = suma + notes[i]; } return suma / notes.length; }

    El paràmetre és un array i el mètode torna un double. El bucle recorre l'array amb notes.length i el resultat ix amb return. Ara este càlcul es pot usar en qualsevol programa.

  9. Per què és bona idea dividir un programa gran en mètodes? Dóna almenys dos motius.

    Solució

    Resposta: Perquè no repetim codi (si cal canviar alguna cosa, es canvia en un sol lloc) i perquè podem provar cada peça per separat i trobar els errors més fàcilment.

    A més, el programa es llig millor: main queda com un resum de passos amb noms que s'entenen. I els mètodes es poden reutilitzar en altres programes.
