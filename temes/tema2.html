Tema 2 · Sessió de 3 hores

Prendre decisions

Un programa que sempre fa el mateix servix de poc. Ara aprendrem a fer que decidisca: si l'usuari té 18 anys, si la contrasenya és correcta, si la nota arriba al 5…

⏱ 3 hores 📦 Fase 1 · Pensament de programador 🧩 Necessites: Temes 0 i 1 ❓ La pregunta clau: quina condició ha de complir-se?

Una situació per començar

🎟️

Un cinema vol calcular el preu de l'entrada: si tens menys de 6 anys, gratis; si tens entre 6 i 17, 6 euros; dels 18 als 64, 9 euros; i si tens 65 o més, 5 euros.

Amb el que sabem fins ara hauríem d'escriure un programa per a cada cas, i no sabríem quin executar. El programa ha de decidir ell tot sol, mirant l'edat que li donem.

Ací comença la part més divertida de programar: fer que el programa pregunte, compare i trie. I hi ha una pregunta que et faràs tota la vida de programador: «quina condició s'ha de complir perquè passe açò?»

30-40 min Explicació i demos
60-75 min Programació guiada
60-75 min Exercicis
15-30 min Repàs i repte
Abans de començar has de poder fer això:
  • Crear variables i guardar-hi valors (Tema 1).
  • Llegir dades pel teclat amb Scanner.
  • Entendre la diferència entre enters i decimals.

Què aprendrem en este tema?

En acabar esta sessió has de saber fer estes coses:

  • 1Comparar dos valors amb ==, !=, <, >, <= i >=.
  • 2Escriure un if i un else i saber què fa cada part.
  • 3Encadenar diversos casos amb else if en l'orde correcte.
  • 4Combinar condicions amb &&, || i !.
  • 5Comparar textos correctament (amb equals, no amb ==).
  • 6Fer menús i opcions amb switch.

Teoria, poc a poc

Una idea → un exemple. I sempre la mateixa pregunta: quina condició ha de complir-se?

1. Comparar dos valors

Per decidir, primer hem de saber comparar. Una comparació no dona un número: dona vertader o fals (true / false), que és justament el tipus boolean que vam vore en el tema anterior.

OperadorEs lligExempleResultat
==és igual a5 == 5true
!=és diferent de5 != 3true
>és més gran que4 > 9false
<és més menut que4 < 9true
>=és més gran o igual que5 >= 5true
<=és més menut o igual que7 <= 5false
 
public class Comparacions {
            public static void main(String[] args) {
                int edat = 16;

                boolean major = edat >= 18;          // guardem el resultat en un boolean
                System.out.println(major);            // false
                System.out.println(edat == 16);       // true
                System.out.println(edat != 16);       // false
            }
        }
Eixida per pantalla 
false
        true
        false
⛔

= no és el mateix que ==. Un sol igual (=) guarda un valor dins d'una variable. Dos iguals (==) comparen. Confondre'ls és l'error número u d'este tema, i Java no sempre t'avisa!

2. El primer if

Un if és una pregunta que fem al programa: si la condició és vertadera, faça açò; si no, res.

public class Aprovat {
            public static void main(String[] args) {
                double nota = 7.5;

                if (nota >= 5) {
                    System.out.println("Estàs aprovat!");
                }

                System.out.println("Fi del programa.");
            }
        }
Eixida per pantalla 
Estàs aprovat!
        Fi del programa.

Fixa't en tres coses de la sintaxi: la condició va entre parèntesis, el codi que s'executa si es complix va entre claus, i el contingut de les claus està indentat per vore-ho clarament.

💡

La pregunta que sempre ens fem: quina condició ha de complir-se perquè passe açò? Ací la resposta és nota >= 5. Si no sabem respondre eixa pregunta, encara no hem pensat bé el problema.

3. I si no es complix: else

else vol dir «si no». Amb if i else cobrim els dos camins possibles: un o l'altre, mai els dos.

public class AprovatOSuspes {
            public static void main(String[] args) {
                double nota = 4.25;

                if (nota >= 5) {
                    System.out.println("Aprovat");
                } else {
                    System.out.println("Suspés");
                }
            }
        }
Eixida per pantalla 
Suspés

Mira el parèntesi de tancament de la condició: no porta punt i coma. Si li'n posem, el if es queda sense cos i el programa fa una cosa estranya sense donar error. Ho tenim en l'apartat d'errors.

4. Més de dos camins: else if

Quan hi ha més de dos casos, s'encadenen les preguntes. Java les mira en orde i entra en la primera que es complica.

public class Notes {
            public static void main(String[] args) {
                double nota = 8.5;

                if (nota < 5) {
                    System.out.println("Insuficient");
                } else if (nota < 7) {
                    System.out.println("Suficient o Bé");
                } else if (nota < 9) {
                    System.out.println("Notable");
                } else {
                    System.out.println("Excel·lent");
                }
            }
        }
Eixida per pantalla 
Notable
⚠️

L'orde importa. Si començarem per nota < 9, un 4.5 també compliria la condició i mai no arribaríem a mirar si és un insuficient. Sempre es posen primer les condicions més concretes (les més estretes) i al final la més àmplia.

5. Combinar condicions

A vegades cal que es complisquen dos coses alhora, o que en baste una. Per a això tenim els operadors lògics.

OperadorEs lligÉs vertader quan…
&&I (a més a més)les dos condicions es complixen
||Oes complix almenys una de les dos
!Nola condició no es complix
 
public class Combinades {
            public static void main(String[] args) {
                int edat = 16;
                boolean teCarnet = false;

                System.out.println(edat >= 18 && teCarnet);   // pot conduir? false
                System.out.println(edat >= 18 || teCarnet);   // alguna cosa?   false
                System.out.println(!teCarnet);                // no té carnet?  true

                boolean adolescent = edat >= 13 && edat <= 19;
                System.out.println(adolescent);               // true
            }
        }
Eixida per pantalla 
false
        false
        true
        true
⛔

En Java no es pot escriure 13 <= edat <= 19, encara que en matemàtiques es faça així. Cal escriure les dos comparacions i unir-les amb &&: edat >= 13 && edat <= 19.

6. Comparar textos: equals

Ací hi ha una trampa molt famosa. Per comparar dos textos no es fa servir ==, sinó el mètode equals():

import java.util.Scanner;

        public class Contrasenya {
            public static void main(String[] args) {
                String clauGuardada = "1234";
                Scanner teclat = new Scanner(System.in);

                System.out.print("Contrasenya: ");
                String clauEscrita = teclat.next();

                System.out.println(clauEscrita == clauGuardada);        // false! ensurt
                System.out.println(clauEscrita.equals(clauGuardada));   // true, segur
            }
        }
Què ha de passar 
Contrasenya: 1234
        false
        true

Sí, has llegit bé: la primera línia dona false encara que els dos textos diguen exactament el mateix. == compara si són el mateix objecte (i el text que arriba pel teclat sempre és un objecte nou), mentres que equals compara si contenen el mateix text. Nosaltres sempre volem el segon.

💡

Regla fàcil de recordar: els textos es comparen amb equals. Sempre. I si no ens importen les majúscules, hi ha equalsIgnoreCase("hola").

7. Menús: switch

Quan totes les decisions depenen de un sol valor i són opcions numerades (un menú, per exemple), hi ha una manera més ordenada d'escriure-ho: switch.

public class Menu {
            public static void main(String[] args) {
                int opcio = 2;

                switch (opcio) {
                    case 1:
                        System.out.println("Nova partida");
                        break;
                    case 2:
                        System.out.println("Carregar partida");
                        break;
                    case 3:
                        System.out.println("Opcions");
                        break;
                    default:
                        System.out.println("Opció desconeguda");
                }
            }
        }
Eixida per pantalla 
Carregar partida

El switch compara el valor amb cada case i entra en el que coincidix. El break fa que s'acabe eixe cas; i default és el cas «si no coincidix cap altre».

ℹ️

Si t'oblides un break, Java continua executant els casos següents. És un error clàssic i es veu de seguida en l'eixida: ixen diversos missatges. Les versions noves de Java tenen una manera d'escriure-ho sense break, però de moment ens quedem amb esta, que funciona en totes les versions.

8. if dins d'un if

Es poden ficar decisions dins de decisions. Es diu niar i és perfectament vàlid, però si n'hi ha moltes el codi es fa difícil de seguir. De moment, prova-ho amb dos nivells com a màxim.

public class Niat {
            public static void main(String[] args) {
                int edat = 20;
                boolean teEntrada = true;

                if (edat >= 18) {
                    if (teEntrada) {
                        System.out.println("Endavant, pots passar.");
                    } else {
                        System.out.println("Primer compra l'entrada.");
                    }
                } else {
                    System.out.println("Ho sent, per a majors de 18 anys.");
                }
            }
        }
Eixida per pantalla 
Endavant, pots passar.
💡

Moltes vegades un if niat es pot escriure en una sola condició: if (edat >= 18 && teEntrada). És més curt i es llix millor. Sempre que pugues, uneix les condicions amb &&.

Exemples explicats pas a pas

Cada exemple: què volem aconseguir, el codi, què apareix per pantalla i per què funciona.

Exemple 1 · Major o menor d'edat

Què volem? Que el programa diga si una persona pot entrar en una web de contingut per a adults.

public class Edats {
            public static void main(String[] args) {
                int edat = 15;

                if (edat >= 18) {
                    System.out.println("Pots entrar: ets major d'edat.");
                } else {
                    System.out.println("Ho sent, cal tindre 18 anys.");
                    System.out.println("Et falten " + (18 - edat) + " anys.");
                }
            }
        }
Eixida per pantalla 
Ho sent, cal tindre 18 anys.
        Et falten 3 anys.

Per què funciona: la condició és edat >= 18. Com que 15 no és major ni igual que 18, la condició és falsa i s'executa el bloc de l'else. I dins d'eixe bloc pugem calcular quants anys falten: 18 − 15.

Exemple 2 · El preu de l'entrada

Què volem? El cinema de la introducció: quatre tarifes segons l'edat. Fixa't en l'orde de les condicions.

public class Cinema {
            public static void main(String[] args) {
                int edat = 70;

                if (edat < 6) {
                    System.out.println("Entrada gratuïta");
                } else if (edat < 18) {
                    System.out.println("Entrada: 6 euros");
                } else if (edat < 65) {
                    System.out.println("Entrada: 9 euros");
                } else {
                    System.out.println("Entrada: 5 euros (jubilats)");
                }
            }
        }
Eixida per pantalla 
Entrada: 5 euros (jubilats)

Per què funciona: les condicions van de menor a major i s'aprofiten les unes de les altres. Quan arribem a l'última, encara que posa només else, ja sabem que l'edat és 65 o més, perquè totes les anteriors han sigut falses.

Exemple 3 · El nivell d'un videojoc

Què volem? Traduir els punts d'un jugador al seu nivell, amb la paraula corresponent.

public class Nivell {
            public static void main(String[] args) {
                int punts = 2450;

                String nivell;
                if (punts < 1000) {
                    nivell = "principiant";
                } else if (punts < 2500) {
                    nivell = "intermedi";
                } else {
                    nivell = "expert";
                }

                System.out.println("Amb " + punts + " punts, el teu nivell és " + nivell + ".");
            }
        }
Eixida per pantalla 
Amb 2450 punts, el teu nivell és intermedi.

Per què funciona: ací no mostrem res dins del if: decidim un valor i el guardem. És un patró molt útil: fer les decisions primer i mostrar el resultat una sola vegada al final.

Exemple 4 · L'accés amb contrasenya

Què volem? Demanar una contrasenya i deixar passar només si encerta. Ací es veu per què cal equals.

import java.util.Scanner;

        public class Acces {
            public static void main(String[] args) {
                String clauCorrecta = "patata123";
                Scanner teclat = new Scanner(System.in);

                System.out.print("Contrasenya: ");
                String clau = teclat.next();

                if (clau.equals(clauCorrecta)) {
                    System.out.println("Accés concedit. Benvingut!");
                } else {
                    System.out.println("Contrasenya incorrecta.");
                }
            }
        }
Què ha de passar 
Contrasenya: patata123
        Accés concedit. Benvingut!

Per què funciona: clau.equals(clauCorrecta) compara el contingut dels dos textos. Si haguerem escrit clau == clauCorrecta, el programa diria sempre «incorrecta» encara que l'usuari l'encertara.

💡

Bonus de seguretat: mai no s'ha d'escriure dins del codi una contrasenya de veritat. Ací ho fem per aprendre, però recorda-ho: el codi el pot llegir tothom.

Què apareixerà per pantalla?

Este és el parany del punt i coma. Pensa què ix abans d'executar.

Pensa abans d'executar

int edat = 12;
        if (edat >= 18);
        {
            System.out.println("Pots conduir");
        }
Resposta
Eixida real
Pots conduir

Per què: El ; al final de la línia del if fa que el if no tinga cos: la condició es comprova i es descarta. El bloc de davall de les claus s'executa SEMPRE, tinga l'edat que tinga. És un error que no dona cap missatge i costa molt de trobar: per això no hem de posar mai ; darrere d'un if.

Programació guiada: ho fem junts

Construïm un programa que valora una nota i diu la qualificació oficial, amb els trams ben ordenats. Pas a pas, com sempre.

1

Lliguem el problema i traiem les condicions

La nota oficial a Formació Professional funciona així: menys de 5 és Insuficient; de 5 a menys de 6, Suficient; de 6 a menys de 7, Bé; de 7 a menys de 9, Notable; i 9 o més, Excel·lent.

Quantes condicions necessitem? I en quin orde les hem de posar?

Tenim quatre trams i un cas final. L'orde natural és de menor a major: nota < 5, nota < 6, nota < 7, nota < 9 i, si cap s'ha complit, ja sabem que és 9 o més → Excel·lent.

2

La primera versió, amb dos trams

Com sempre, comencem pel més simple i el provem: aprovat o suspés.

import java.util.Scanner;

          public class Qualificacio {
              public static void main(String[] args) {
                  Scanner teclat = new Scanner(System.in);

                  System.out.print("Escriu la nota: ");
                  double nota = teclat.nextDouble();

                  if (nota < 5) {
                      System.out.println("Insuficient");
                  } else {
                      System.out.println("Aprovat");
                  }
              }
          }
Què ha de passar 
Escriu la nota: 6.5
          Aprovat
3

Afegim els trams intermedis

Ara encadenem els else if. L'orde és el que fa que funcione: cada condició només pot ser vertadera si les anteriors són falses.

I si posàrem primer nota < 9? Què passaria amb una nota de 4.5?

4

Provem-ho amb casos límit

Els casos límit són els que estan just en la frontera: 4.99, 5.0, 5.99, 6.0, 8.99, 9.0. Sempre es proven: és on solen aparéixer els errors.

NotaQuè ha d'eixirPer què
4.99InsuficientÉs més menuda que 5
5.0SuficientNo complix < 5, però sí < 6
8.99NotableNo complix < 7, però sí < 9
9.0Excel·lentNo complix cap condició → else
💡

Regla d'or: prova sempre el valor just de la frontera. Si el programa funciona amb 8.99 i amb 9.0, les fronteres estan bé.

5

Trenquem-lo a propòsit

Provem tres coses i apuntem què passa:

  1. Una nota de 12 → diu Excel·lent, i està mal dit: hauríem d'haver comprovat abans que la nota està entre 0 i 10.
  2. Una nota de −3 → diu Insuficient, i tampoc no és correcte.
  3. Una lletra → InputMismatchException, com en el tema anterior.

Comprovem-ho i decidim: afegiríem una comprovació al principi que diga «això no és una nota». Eixa idea — comprovar les dades abans de treballar amb elles — és una de les coses que distingix un programa amateur d'un de bo. I ho farem més avant amb més ferramentes.

import java.util.Scanner;

          public class Qualificacio {
              public static void main(String[] args) {
                  Scanner teclat = new Scanner(System.in);

                  System.out.print("Escriu la nota: ");
                  double nota = teclat.nextDouble();

                  if (nota < 0 || nota > 10) {
                      System.out.println("Eixa nota no és possible: ha d'estar entre 0 i 10.");
                  } else if (nota < 5) {
                      System.out.println("Insuficient");
                  } else if (nota < 6) {
                      System.out.println("Suficient");
                  } else if (nota < 7) {
                      System.out.println("Bé");
                  } else if (nota < 9) {
                      System.out.println("Notable");
                  } else {
                      System.out.println("Excel·lent");
                  }
              }
          }
Què ha de passar 
Escriu la nota: 12
          Eixa nota no és possible: ha d'estar entre 0 i 10.

Mini exercicis

Activitats molt curtes per agafar soltura amb les condicions.

1

Vertader o fals?

Fàcil 2 min
Sense executar-lo, digues què mostrarà cada línia. Després comprova-ho.
int a = 7;
System.out.println(a > 5);
System.out.println(a == 7);
System.out.println(a != 7);
Solució proposada 
int a = 7;
System.out.println(a > 5);    // true
System.out.println(a == 7);   // true
System.out.println(a != 7);   // false
Eixida per pantalla 
true
true
false

Per què es fa aixina: Les comparacions donen sempre true o false. El primer: 7 és més gran que 5. El segon: 7 és igual a 7. El tercer: 7 no és diferent de 7, per tant és fals.

2

Pot conduir?

Fàcil 3 min
Crea una variable amb una edat i mostra «Pot conduir» si és 18 o més, i «No pot conduir» si no.
Solució proposada 
public class Conduir {
    public static void main(String[] args) {
        int edat = 17;

        if (edat >= 18) {
            System.out.println("Pot conduir");
        } else {
            System.out.println("No pot conduir");
        }
    }
}
Eixida per pantalla 
No pot conduir

Per què es fa aixina: La condició edat >= 18 inclou el 18 exactament gràcies al signe >= (major o igual). Si haguerem posat >, una persona de 18 anys justos no podria conduir.

3

Parell o senar

Intermèdia 3 min
Utilitza el residu (%) i un if per dir si un número és parell o senar.
Solució proposada 
public class Parell {
    public static void main(String[] args) {
        int numero = 7;

        if (numero % 2 == 0) {
            System.out.println("És parell");
        } else {
            System.out.println("És senar");
        }
    }
}
Eixida per pantalla 
És senar

Per què es fa aixina: Si el residu de dividir per 2 és zero, el nombre és parell. És la primera cosa útil que fem amb l'operador % del tema anterior.

4

Troba l'error

Intermèdia 3 min
Este programa no compila. Copia'l, llig el missatge i arregla'l.
int nota = 6;
if (nota = 5) {
    System.out.println("Justet");
}

Pista: Mira els operadors de comparació. N'hi ha un que és per assignar i un altre per comparar.

Solució proposada 
int nota = 5;
if (nota == 5) {
    System.out.println("Justet");
}
Eixida per pantalla 
Justet

Per què es fa aixina: Amb un sol = estem intentant guardar el 5 dins de nota, i el resultat d'una assignació és un número, no un vertader/fals. El if espera un boolean: per això Java dona error incompatible types. Amb == sí que comparem.

5

Escriu la condició

Intermèdia 3 min
Volem comprovar si una edat està entre 13 i 19 anys (els dos inclosos). Escriu la condició correcta en Java.
Solució proposada 
int edat = 16;

if (edat >= 13 && edat <= 19) {
    System.out.println("És adolescent");
}
Eixida per pantalla 
És adolescent

Per què es fa aixina: En Java no es pot escriure 13 <= edat <= 19. Cal fer les dos comparacions i unir-les amb &&: que siga 13 o més i 19 o menys.

6

La contrasenya correcta

Intermèdia 4 min
Demana una paraula a l'usuari i digues si coincidix amb la contrasenya «hola123».

Com ha de funcionar:

Exemple d'ús 
Escriu la contrasenya: hola123
Què ha d'aparéixer 
Contrasenya correcta
Solució proposada 
import java.util.Scanner;

public class Clau {
    public static void main(String[] args) {
        Scanner teclat = new Scanner(System.in);

        System.out.print("Escriu la contrasenya: ");
        String clau = teclat.next();

            System.out.println("Contrasenya correcta");

Escriu la contrasenya: hola123

Per què es fa aixina: Els textos sempre es comparen amb equals. Si hages escrit clau == "hola123", el programa hauria dit «incorrecta» encara que l'usuari l'encertara.

7

El menú del joc

Intermèdia 4 min
Demana un número de l'1 al 3 i mostra què s'ha triat: 1 → «Nova partida», 2 → «Carregar», 3 → «Opcions». Si és una altra cosa, «Opció no vàlida».

Com ha de funcionar:

Exemple d'ús 
Tria una opció: 2
Què ha d'aparéixer 
Carregar partida
Solució proposada 
import java.util.Scanner;

public class MenuJoc {
    public static void main(String[] args) {
        Scanner teclat = new Scanner(System.in);

        System.out.print("Tria una opció: ");
        int opcio = teclat.nextInt();

        switch (opcio) {
            case 1:
                System.out.println("Nova partida");
                break;
            case 2:
                System.out.println("Carregar partida");
                break;
            case 3:
                System.out.println("Opcions");
                break;
            default:
                System.out.println("Opció no vàlida");
        }
    }
}
Què ha de passar 
Tria una opció: 2
Carregar partida

Per què es fa aixina: Amb switch el codi queda més pla i més fàcil de llegir que amb tres else if. No t'oblides dels break: si en falta un, s'executen també els casos següents.

Fes el programa

Quatre exercicis complets. Recorda: primer pensa quina condició ha de complir-se, després escriu el codi.

1

Aprovat o suspés

Fàcil 12 min
Demana una nota (pot tindre decimals) i mostra «Aprovat» si és 5 o més i «Suspés» si no. Afig també quant punts falten per aprovar quan estiga suspés.

Com ha de funcionar:

Exemple d'ús 
Nota: 4.25
Què ha d'aparéixer 
Suspés
Et falten 0.75 punts per aprovar.

Pista: La resta per saber què falta es fa dins del bloc de l'else, no fora.

Solució proposada 
import java.util.Scanner;

public class Nota {
    public static void main(String[] args) {
        Scanner teclat = new Scanner(System.in);

        System.out.print("Nota: ");
        double nota = teclat.nextDouble();

        if (nota >= 5) {
            System.out.println("Aprovat");
        } else {
            System.out.println("Suspés");
            System.out.println("Et falten " + (5 - nota) + " punts per aprovar.");
        }
    }
}
Què ha de passar 
Nota: 4.25
Suspés
Et falten 0.75 punts per aprovar.

Per què es fa aixina: La resta 5 - nota es fa només quan estem en el bloc de l'else, és a dir, només quan realment ha suspés. Este és un bon exemple de com les decisions ens estalvien càlculs inútils.

2

El control d'accés del videojoc

Intermèdia 20 min
Demana un nom d'usuari i una contrasenya. L'accés s'ha de concedir només si l'usuari és «admin» i la contrasenya és «java2026». Si l'usuari és correcte però la contrasenya no, digues «Contrasenya incorrecta». Si l'usuari ja està mal, digues «Usuari desconegut».

Com ha de funcionar:

Exemple d'ús 
Usuari: admin
Contrasenya: 1234
Què ha d'aparéixer 
Contrasenya incorrecta

Pista: L'operador ! davant de usuari.equals("admin") significa «si NO és admin».

Solució proposada 
import java.util.Scanner;

public class Control {
    public static void main(String[] args) {
        Scanner teclat = new Scanner(System.in);

        System.out.print("Usuari: ");
        String usuari = teclat.next();

        System.out.print("Contrasenya: ");
        String clau = teclat.next();

        if (!usuari.equals("admin")) {
            System.out.println("Usuari desconegut");
        } else if (clau.equals("java2026")) {
            System.out.println("Accés concedit. Endavant!");
        } else {
            System.out.println("Contrasenya incorrecta");
        }
    }
}
Què ha de passar 
Usuari: admin
Contrasenya: 1234
Contrasenya incorrecta

Per què es fa aixina: Els dos textos es comparen amb equals i l'operador ! invertix el resultat de la comparació de l'usuari. L'orde de les comprovacions és lògic: primer mirem si l'usuari existix, i només si existix passem a comprovar la contrasenya.

3

El preu de l'entrada del cinema

Intermèdia 20 min
Demana l'edat i mostra el preu segons els quatre trams: menys de 6 anys, gratis; de 6 a 17 anys, 6 euros; de 18 a 64 anys, 9 euros; 65 o més, 5 euros. A més, quan el client siga menor d'edat, mostra també un missatge que diga que pot demanar el descompte de família nombrosa.

Com ha de funcionar:

Exemple d'ús 
Edat: 16
Què ha d'aparéixer 
Entrada: 6 euros
Pots demanar el descompte de família nombrosa.

Pista: Escriu les condicions de menor a major i deixa l'else per a l'últim tram. El missatge del descompte és un if independent, fora de la cadena.

Solució proposada 
import java.util.Scanner;

public class Cinema {
    public static void main(String[] args) {
        Scanner teclat = new Scanner(System.in);

        System.out.print("Edat: ");
        int edat = teclat.nextInt();

        if (edat < 6) {
            System.out.println("Entrada gratuïta");
                } else if (edat < 18) {
            System.out.println("Entrada: 6 euros");
        } else if (edat < 65) {
            System.out.println("Entrada: 9 euros");
        } else {
            System.out.println("Entrada: 5 euros");
        }

        if (edat < 18) {
            System.out.println("Pots demanar el descompte de família nombrosa.");
        }
    }
}
Què ha de passar 
Edat: 16
Entrada: 6 euros
Pots demanar el descompte de família nombrosa.

Per què es fa aixina: L'escala de trams de preu va amb else if perquè són exclusions: només un dels quatre preus pot ser el bo. El descompte de família nombrosa, en canvi, és una condició independent del preu, i per això va en un if a banda i no dins de la cadena.

4

La màquina de begudes

Cal pensar 25 min
Fes el menú de la màquina de begudes amb switch: 1 → Aigua (1 euro), 2 → Suc (1.50 euros), 3 → Cafè (1.20 euros), 4 → Refresc (1.80 euros). Després demana els diners que introdueix l'usuari i digues si en té prou i quants diners li falten o li sobren.

Com ha de funcionar:

Exemple d'ús 
Tria una beguda: 2
Diners introduïts: 1.0
Què ha d'aparéixer 
Has triat Suc (1.5 euros)
Et falten 0.5 euros

Pista: Guarda el preu en una variable dins de cada case i, al final, fes les comprovacions dels diners fora del switch.

Solució proposada 
import java.util.Scanner;

public class Maquina {
    public static void main(String[] args) {
        Scanner teclat = new Scanner(System.in);

        System.out.print("Tria una beguda: ");
        int opcio = teclat.nextInt();

        double preu;
        String nom;

        switch (opcio) {
            case 1:
                nom = "Aigua";
                preu = 1.00;
                break;
            case 2:
                nom = "Suc";
                preu = 1.50;
                break;
            case 3:
                nom = "Cafè";
                preu = 1.20;
                break;
            case 4:
                nom = "Refresc";
                preu = 1.80;
                break;
            default:
                nom = "";
                preu = 0;
                System.out.println("Eixa opció no existix.");
        }

        if (preu > 0) {
            System.out.println("Has triat " + nom + " (" + preu + " euros)");

            System.out.print("Diners introduïts: ");
            double diners = teclat.nextDouble();

            if (diners >= preu) {
                System.out.println("Gràcies! El teu canvi és " + (diners - preu) + " euros");
            } else {
                System.out.println("Et falten " + (preu - diners) + " euros");
            }
        }
    }
}
Què ha de passar 
Tria una beguda: 2
Has triat Suc (1.5 euros)
Diners introduïts: 1.0
Et falten 0.5 euros

Per què es fa aixina: El switch ens servix per triar el producte i guardar-ne el nom i el preu. Després, amb un if anidat, tornem a decidir segons els diners. Fixa't que llegim els diners després del menú: si l'opció no existix, no té sentit demanar-los. Els nombres decimals s'escriuen amb punt: 1.0.

Reptes (sense solució)

🧠

Els reptes no tenen botó de solució, a propòsit. L'objectiu és pensar, provar, equivocar-se i tornar-ho a intentar. Es poden resoldre de moltes maneres diferents: totes les solucions que funcionen són bones.

REPTE 1

L'any de traspàs

Un any és de traspàs (té 366 dies) si es complixen estes condicions: és divisible per 4, excepte si és divisible per 100; però si és divisible per 400, sí que és de traspàs.

Demana un any i digues si és de traspàs o no. El repte està a combinar bé els operadors %, && i ||.

Per anar més enllà:

  • Comprovar-ho amb els anys 2000, 1900, 2024 i 2026.
  • Dir també quants dies té el mes de febrer d'eixe any.
REPTE 2

El joc de les tres preguntes

Fes un programa que faça tres preguntes a l'usuari (les que vulgues) i que comprove les respostes. Al final ha de dir quantes n'ha encertat de tres i un missatge diferent segons el resultat: 3 → «perfecte», 2 → «molt bé», 1 → «cal repassar», 0 → «tornem a començar».

Necessitaràs una variable per comptar els encerts i sumar-li 1 cada vegada que s'encerta. I recorda que els textos es comparen amb equals.

Per anar més enllà:

  • Que les respostes no distingisquen majúscules de minúscules (equalsIgnoreCase).
  • Que al final es mostre també un percentatge d'encerts (encerts / 3 × 100).

Errors habituals

Els errors habituals d'este tema. Alguns no donen missatge d'error: ixen malament i ja està. Eixos són els perillosos.

Error 1

Confondre = amb ==

Codi que falla 
int nota = 6;
if (nota = 5) {
    System.out.println("Justet");
}

error: incompatible types: int cannot be converted to boolean if (nota = 5) {

Què ha passat
Hem escrit un sol igual dins de la condició.
Per què
Un sol = guarda un valor i dona com a resultat un número; el if necessita un boolean. Dos iguals (==) comparen i donen true o false.
Com detectar-ho
El missatge diu int cannot be converted to boolean, i assenyala la línia de la condició.
Com corregir-ho
Posa els dos iguals: nota == 5. Consell per a la vida: si el compilador es queixa d'una comparació, mira els iguals.
Codi correcte 
int nota = 6;
if (nota == 5) {
    System.out.println("Justet");
}
Error 2

Punt i coma darrere del if (no dona error!)

Codi que falla 
int edat = 12;
if (edat >= 18);
{
    System.out.println("Pots conduir");
}
Què ha passat
El programa mostra «Pots conduir» a una persona de 12 anys, i no dona cap missatge d'error.
Per què
El ; ha deixat el if sense cos: la condició es comprova i es descarta. Les claus que venen després són un bloc solt, que s'executa sempre.
Com detectar-ho
No hi ha error de compilació: s'ha de detectar provant el programa amb un valor que NO hauria de passar. És l'error més perillós de tots.
Com corregir-ho
Lleva el ; i queda't amb les claus: if (condicio) { ... }.
Codi correcte 
int edat = 12;
if (edat >= 18) {
    System.out.println("Pots conduir");
}
Error 3

Comparar textos amb ==

Codi que falla 
String clau = teclat.next();
if (clau == "hola") {
    System.out.println("Endavant");
}
Què ha passat
El programa diu que la contrasenya és incorrecta encara que l'usuari l'escriga bé.
Per què
Amb els textos, == compara si són el mateix objecte, no si diuen el mateix. Un text que arriba pel teclat mai no és el mateix objecte que un text escrit dins del codi.
Com detectar-ho
El programa compila i funciona, però les comparacions de text sempre donen fals. I no hi ha cap missatge d'error.
Com corregir-ho
Fes servir equals: clau.equals("hola"). Si no importen les majúscules: clau.equalsIgnoreCase("hola").
Codi correcte 
String clau = teclat.next();
if (clau.equals("hola")) {
    System.out.println("Endavant");
}
Error 4

L'orde dels else if

Codi que falla 
if (edat < 65) {
    System.out.println("Entrada: 9 euros");
} else if (edat < 6) {
    System.out.println("Gratis");
}
Què ha passat
Un xiquet de 3 anys ha de pagar 9 euros i no arriba mai al cas «gratis».
Per què
Java mira els else if en orde i entra en el primer que es complica. Si la condició més àmplia va primera, es menja tots els casos.
Com detectar-ho
Prova el programa amb els casos extrems. Si un cas «impossible» eix, l'orde està mal posat.
Com corregir-ho
Ordena les condicions de la més concreta a la més general (de menor a major, si són trams d'edat o de punts).
Codi correcte 
if (edat < 6) {
    System.out.println("Gratis");
} else if (edat < 65) {
    System.out.println("Entrada: 9 euros");
}
Error 5

Condicions encadenades com en matemàtiques

Codi que falla 
if (13 <= edat <= 19) {

error: bad operand types for binary operator '<=' if (13 <= edat <= 19) {

Què ha passat
Hem escrit la condició com la diríem en matemàtiques.
Per què
En Java, 13 <= edat ja dona un resultat (true o false), i no es pot comparar eixe resultat amb 19. Cal escriure les dos comparacions.
Com detectar-ho
El missatge parla d'operadors que no es poden usar junts.
Com corregir-ho
Uneix les dos comparacions amb &&: edat >= 13 && edat <= 19.
Codi correcte 
if (edat >= 13 && edat <= 19) {
Error 6

Oblidar les claus i pensar que afecten més línies

Codi que falla 
if (nota >= 5)
    System.out.println("Aprovat");
    System.out.println("Enhorabona!");
Què ha passat
El segon missatge s'escriu sempre, haja aprovat o no.
Per què
Sense claus, el if només controla la primera línia que té davall. La segona ja no depén de la condició.
Com detectar-ho
Compila sense errors, però el missatge apareix en casos que no toquen. Es detecta provant.
Com corregir-ho
Posa claus sempre, encara que dins només hi haja una línia. Estalvia este error i fa el codi més llegible.
Codi correcte 
if (nota >= 5) {
    System.out.println("Aprovat");
    System.out.println("Enhorabona!");
}

Resum visual

Les idees que has d'endur-te d'este tema.

Les comparacions (==, !=, <, >, <=, >=) donen sempre true o false.

= guarda un valor; == compara. Confondre'ls és l'error més habitual.

if fa una cosa si es complix la condició; else fa l'altra.

else if encadenen casos i es miren en orde: del més concret al més general.

&& cal que es complisquen les dos coses; || en basta una; ! invertix.

Els textos es comparen amb equals, mai amb ==.

switch va bé per a menús i opcions; no t'oblides dels break.

La pregunta clau sempre: quina condició ha de complir-se perquè passe açò?

Autoavaluació

Nou preguntes. Pensa-les abans de mirar la solució.

  1. Quina diferència hi ha entre = i ==?

    • No hi ha cap diferència.
    • = guarda un valor en una variable i == compara dos valors.
    • = compara i == guarda.
    Solució

    Resposta: b) = guarda i == compara.

    Un sol igual assigna (guarda); dos iguals comparen i donen true o false. Per això dins d'un if sempre van dos iguals.

  2. Què mostrarà este programa?

    int x = 10;
if (x > 5) {
    System.out.println("Gran");
} else {
    System.out.println("Petit");
}
    Solució

    Resposta: Gran

    La condició x > 5 és vertadera perquè 10 és més gran que 5. Quan la condició es complix, s'executa el bloc del if i mai el de l'else.

  3. Amb què es comparen dos textos en Java?

    • ==
    • equals()
    • >
    Solució

    Resposta: b) equals()

    Amb textos, == compara si són el mateix objecte, no si diuen el mateix. El mètode equals() compara el contingut.

  4. Escriu la condició per comprovar si una nota està aprovada (5 o més) i a més no arriba a 7.

    Solució

    Resposta: nota >= 5 && nota < 7

    Han de complir-se les dos coses alhora, per tant s'unixen amb &&. Fixa't que el 7 queda fora (<) i el 5 entra (>=).

  5. Este programa hauria de dir «Pots passar» només a majors de 18 anys. Funciona?

    int edat = 15;
if (edat >= 18);
{
    System.out.println("Pots passar");
}
    Solució

    Resposta: No: el punt i coma després del if fa que el missatge s'escriga sempre.

    El punt i coma tanca el if sense cos. El bloc de les claus passa a ser codi solt. És perillós perquè no dona cap error: només es detecta provant el programa.

  6. Quina diferència hi ha entre && i ||?

    Solució

    Resposta: && necessita que es complisquen les dos condicions; || en necessita només una.

    Es llig && com «i» i || com «o». Exemple: per a entrar al cine amb descompte cal ser menor i vindre acompanyat; per a agafar el bus, tindre targeta o diners en efectiu.

  7. Què mostrarà este programa?

    int opcio = 3;
switch (opcio) {
    case 1:
        System.out.println("U");
    case 3:
        System.out.println("Tres");
        break;
    default:
        System.out.println("Altre");
}
    Solució

    Resposta: Tres

    La coincidència és el case 3, que té break i s'acaba. Si al case 3 li faltara el break, s'executaria també el default i eixiria «Tres» i «Altre».

  8. Este codi compila? Per què?

    int edat = 16;
if (13 <= edat <= 19) {
    System.out.println("Adolescent");
}
    Solució

    Resposta: No compila: en Java no es poden encadenar comparacions així.

    13 <= edat ja dona true o false, i no es pot comparar eixe resultat amb 19. Cal escriure edat >= 13 && edat <= 19.

  9. Volem un programa que diga si un any és de traspàs. Escriu la condició completa (divisible per 4, però no per 100, excepte si és divisible per 400).

    Solució

    Resposta: (any % 4 == 0 && any % 100 != 0) || any % 400 == 0

    Els parèntesis agrupen la primera part («divisible per 4 i no per 100») i després la segona excepció («o divisible per 400»). Sense els parèntesis, && i || es barregen i el resultat no és el que volem. Comprovem-ho amb 2000 (sí), 1900 (no), 2024 (sí) i 2026 (no).
